# 金币倍率与进度恢复设计

## 1. 产品决策

永久金币倍率纳入首版，候选值为 `1× / 2× / 3×`：

- 公开安装默认 `1×`，避免安装即改变经济；
- 配置界面将 `2×` 标为 Recommended；
- `3×` 提供给已经重复开荒或明确希望缩短刷取时间的玩家；
- 切换倍率只影响未来收入，不处理已有余额。

一次性大量金币不与倍率混为一个开关。它属于后续的 Progress Recovery：默认隐藏、手动输入、操作前备份、显示旧值和新值并二次确认。

## 2. 为什么属于项目范围

- 已有 GoldPatcher/GoldEditor 证明了真实需求；
- 当前用户因没有可用云存档而从头开始，验证了设备迁移场景；
- 2× 仍保留游玩、获得、购买和解锁循环；
- 与加速、去 Zoom 一样，它减少重复劳动，而不替玩家选择格子；
- 一个模块化 QoL 套件比多个互不兼容的小补丁更容易安装、恢复和维护。

## 3. 当前技术实现

当前配置化实现不直接编辑 LevelDB/IndexedDB，也不修改已有余额。它按 `1×/2×/3×` 在 Construct 事件表中分别复制 0/20/40 个永久金币收入动作：

| 类别 | 原动作数 | 2× 副本数 | 影响 |
|---|---:|---:|---|
| 正常/特殊离场结算 | 12 | 12 | 当前余额与累计获得量 |
| 死亡保留结算 | 6 | 6 | 当前余额与累计获得量 |
| 直接存入/出售 | 2 | 2 | 当前余额 |
| 合计 | 20 | 20 | 仅永久金币收入 |

明确不复制：

- 存档载入和当前余额赋值；
- 局外升级购买扣款；
- 官方一次性 Offer；
- 剧情固定赠送；
- 局内金币拾取、商店价格和消费；
- 其他资源、生命、概率和解锁状态。

## 4. 构建与验证

内部 Alpha 安装不含 Turbo 的 Recommended 配置：

```powershell
node tools\fast-cesto.mjs install SolCesto config\fast-cesto.recommended.json backups\epic-1.01.3
```

独立验证命令：

```powershell
node tools\verify-prototype.mjs backups\epic-1.01.3\assets.dat build\prototype-1.01.3-speed-1.5-gold-2-no-move-zoom
```

验证器检查原版/原型哈希、仅两个归档条目发生变化、速度补丁、Zoom 删除、20 个收入动作、20 个副本以及四个代表性的排除动作。

## 5. 动态测试矩阵

| 场景 | 1× 期望 | 2× 期望 | 不能发生 |
|---|---:|---:|---|
| 正常离场结算 N | +N | +2N | 重复结算 |
| 死亡保留 N | +N | +2N | 绕过死亡保留规则 |
| 存入 1 金币 | +1 | +2 | 局内扣除变成 2 |
| 出售价值 1 | +1 | +2 | 出售动画执行两次 |
| 花费 N | -N | -N | 扣除翻倍 |
| 官方/剧情赠送 N | +N | +N | 非游玩奖励翻倍 |
| 载入已有余额 N | N | N | 启动即变成 2N |

还要检查最终余额、累计获得量、标题动画、奖励文字和成就计数是否一致。

## 6. 一次性金币恢复的安全要求

该功能尚未实现。进入开发前必须满足：

1. 只操作 `c3-localstorage-*` 中确认过的游戏 key，不扫描或复制 Epic 凭证；
2. 关闭游戏后操作，拒绝与游戏并发写入；
3. 备份相关 IndexedDB/LevelDB 文件并记录哈希；
4. 优先提供“设置最终余额”，避免“追加”按钮误点多次；
5. 默认不显示，进入 Advanced 后再次确认；
6. 日志只记录旧值/新值和哈希，不记录无关存档内容；
7. 支持恢复操作前状态。
