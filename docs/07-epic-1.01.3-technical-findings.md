# Epic 1.01.3 实机技术报告

> 勘察日期：2026-08-11
> 目标版本：Windows / Epic Games Store / 游戏内版本 `1.01.3`
> 决策：**Go（固定倍率、定点关闭移动 Zoom 与永久金币倍率均已实现原型）**

## 1. 实际封装

- 游戏是 Construct 3 的 Windows WebView2 导出，不是旧版 NW.js；
- 主内容位于 `SolCesto/www/assets.dat`；
- `assets.dat` 是 Construct 3 的 `c3ab` 自定义归档，含 1010 个连续、未压缩条目；
- 归档可以无损解析和重打包：对原始条目做零修改重打包后，整个文件的 SHA-256 与原版完全一致；
- 无需 DLL 注入、绕过 DRM、修改主 EXE 或提取 Epic 凭证。

基线指纹见 [research/epic-1.01.3-baseline.json](../research/epic-1.01.3-baseline.json)。不要公开 `package.json` 的内容，其中含 Epic 客户端配置；公开报告只保留不敏感的哈希和结构信息。

## 2. 已定位的修改点

### 固定 1.5× 速度

原型在 `scripts/c3runtime.js` 中设置默认时间倍率，并包装中央 `SetTimeScale` 入口：

- 正常游戏的基础倍率 `1` 映射为 `1.5`；
- 游戏主动设置 `0` 的 freeze-frame 仍保持 `0`；
- 游戏恢复到 `1` 时回到 `1.5`，不会意外把 Mod 关掉；
- 该方案避免逐项修改 Tween、计时器和动画事件。

### 只关闭行动 Zoom

在 `data.json` 的 `camera_zoomCase` 中定位到唯一的 Tween action，SID 为 `938984979377417`。原型只移除这一个 action，保留：

- `camera_zoomBiome`；
- 六个屏幕震动相关函数；
- 相机跟随；
- 返回镜头 Tween；
- 菜单、布局适配和叙事镜头逻辑。

这比锁死整个 Layout scale 更窄，误伤其他镜头的概率更低。

## 3. 原型与改动边界

当前原型目录：`build/prototype-1.01.3-speed-1.5-gold-2-no-move-zoom/`

归档比较结果：

- 条目总数：1010；
- 新增：0；
- 删除：0；
- 改动：2；
- 改动条目：`scripts/c3runtime.js`、`data.json`。

该目录是早期技术验证包，功能固定为 `1.5× + 关闭行动 Zoom + 永久金币 2×`。当前开发已由 `tools/fast-cesto.mjs` 接管：可从正版备份按严格配置在本机重建归档，不需要把完整游戏文件放入发布包；Turbo Worker、本地配置 UI、脱敏日志/诊断和封闭 Alpha 候选包均已实现。

完整 `assets.dat` 含正版游戏资源，只能用于本机测试，**不得上传、提交仓库或放入 Release**。

## 4. 安装与恢复安全性

早期 `tools/manage-prototype.mjs` 已验证固定原型的往返恢复；当前 `tools/fast-cesto.mjs` 进一步实现：

- 只接受已知原版哈希或状态清单登记的已安装哈希；
- 未知版本 fail closed；
- 安装前保存原版备份并验证哈希；
- 每次从正版备份重新生成，支持安全跨配置重建；
- 交换前落盘事务日志；下次启动按日志和实际哈希提交或回滚中断操作；
- 通过单操作锁、游戏运行检测、磁盘空间预检和已验证的临时文件降低并发及文件错误风险；
- 支持 `status`、`install` 和 `restore`。

已完成同配置幂等、跨配置重建、`restore → status → install`、未知测试文件拒绝和 8 个中断落点恢复。恢复后的 `assets.dat` 与原版 SHA-256 完全一致。当前收尾状态为：Turbo Preview 配置已安装，原版备份与状态清单有效。

## 5. 永久金币 2× 原型

新版归档 SHA-256：`DFA2A1CB450B04EEC80B5A27BD1B677255C5CBD1175DB43F20985F1D319F2EA1`。

构建器在 `data.json` 中验证并复制 20 个确定的收入动作：正常/特殊离场结算、死亡保留结算、直接存入和出售所得。每个副本使用新的唯一 SID，并与原动作除 SID 外完全一致。

自动验证保证：

- 原始 20 个动作各出现一次，2× 对应 20 个副本；
- 只改动 `scripts/c3runtime.js` 与 `data.json` 两个归档条目；
- 行动 Zoom action 仍不存在；
- 官方 Offer、剧情赠送和两项局外消费动作仍各出现一次；
- 新版归档与 manifest 哈希一致；
- 游戏启动到标题界面正常。

用户已通过自然游玩完成一次正常永久金币结算，确认最终余额实际增加 `2×`；该结论覆盖正常结算，不自动代表死亡、特殊离场、直接存入和出售路径已经动态验证。

## 6. 实机证据

### 速度

同样在启动后约 32 秒观察：

- 原版仍处于开场动画房间；
- 1.5× 原型已经进入标题/菜单过渡。

这证明全局倍率至少覆盖了目标开场和主要时间推进。它不能代替完整 Run、音频和极端事件回归。

### 行动 Zoom

对原版和原型执行相同的整行点击，并在 50/150/300/600/1000/2000 ms 截图：

- 原版 150 ms：棋盘明显放大，边缘格子被裁切；
- 原型 150 ms：棋盘保持原始构图；
- 原型同时正常显示伤害结算与角色移动；
- 原型 2000 ms：事件仍继续，没有卡在 freeze-frame。

因此，“只移除行动 Zoom”已通过实机 A/B，而不是只靠静态代码推断。
