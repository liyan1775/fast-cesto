# 事务恢复与故障安全

> 范围：Epic Windows `1.01.3` 内部 Alpha 本地补丁器。目标是让一次安装、重配或恢复最终只处于“完整旧版本”或“完整新版本”，不会静默接受半交换状态。

## 1. 事务协议

每次写入遵循以下顺序：

1. 从哈希验证过的正版备份生成并验证新 `assets.dat` stage；
2. 生成并验证新的安装状态 stage；
3. 在第一次 rename 前原子写入 `transaction.json`，记录操作类型、新旧归档哈希、新旧状态哈希和所有临时文件名；
4. 将旧文件移动到同目录 swap，再将 stage 移到正式路径；
5. 验证正式路径哈希后删除 swap 和事务日志。

文件名只接受工具生成的 UUID 格式，日志中的路径不能越出游戏或状态目录。

## 2. 启动恢复规则

补丁器每次启动先获取单操作锁，再检查游戏进程和事务日志。恢复不相信日志里的“阶段编号”，而是读取当前正式文件、stage 和 swap 的实际 SHA-256：

- 新归档已经就位，且新状态已就位或仍在已验证 stage：完成提交；
- 新归档尚未完整就位：从已验证 swap 恢复旧归档和旧状态；
- 任意关键文件既不匹配旧哈希也不匹配新哈希：停止并保留证据，不猜测；
- 没有事务日志的孤立 stage：可删除；
- 没有事务日志的 swap：停止并要求人工检查。

如果游戏仍在运行，恢复、安装和还原都不会触碰归档。

## 3. 前置防护与错误

- 单操作锁阻止两个补丁进程同时交换文件，崩溃遗留的陈旧锁可自动回收；
- 在备份、构建和恢复复制前检查可用空间，并额外保留 16 MiB 余量；
- 游戏运行中安装会明确要求关闭 `SolCesto.exe`；
- `ENOSPC`、文件占用、无权限和缺失文件会转换为可操作的错误说明；
- 未知游戏归档、损坏备份、无效配置或无效状态清单一律 fail closed。

## 4. 已验证矩阵

| 场景 | 结果 |
|---|---|
| 日志已写、尚未交换 | 回滚旧归档与旧状态 |
| 旧归档已移走 | 从 swap 回滚 |
| 新归档已就位、状态未提交 | 补齐并提交新状态 |
| 新归档和新状态已就位、临时文件未清理 | 保留新版本并清理 |
| 首次安装无旧状态、新归档已就位 | 提交新状态 |
| 恢复原版已经就位 | 提交恢复并清理 |
| 恢复操作只移走旧归档 | 从 swap 回滚 |
| 日志包含越界/非法文件名 | 拒绝，正式归档不变 |
| 活跃锁 / 陈旧锁 | 拒绝并发 / 自动回收 |
| 孤立 stage / 无日志 swap | 自动清理 / fail closed 并保留 |
| 游戏运行中安装 | 拒绝，归档哈希不变 |
| 人工制造空间不足 | 写入前返回 `ENOSPC` |
| 235 MB 真实归档往返 | 原版哈希精确恢复，Turbo Preview 可再次安装 |

自动测试入口：

```powershell
node tools\test-transaction-recovery.mjs
node tools\test-fast-cesto.mjs
```

## 5. 剩余边界

- 不主动制造真实断电；隔离测试覆盖等价的关键文件落点，但仍需封闭 Alpha 收集自然崩溃数据；
- 只读目录提示已实现，尚未在本机修改 ACL 单独验证；
- 结构化诊断包已实现并通过路径/内容脱敏测试；封闭 Alpha 仍需验证不同权限、杀软和崩溃环境中的自然恢复结果。
