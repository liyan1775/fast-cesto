# 本地 UI、诊断与封闭 Alpha 包

> 当前版本：`v0.1.0-alpha.1` 候选包。它已通过本机自动化和浏览器回归，但尚未经过 3–5 台外部 Epic 环境验证。

## 1. 本地配置界面

在项目或候选包根目录双击 `start-fast-cesto.cmd`，或运行：

```powershell
node tools\fast-cesto-ui.mjs
```

服务只绑定随机的 `127.0.0.1` 端口并打开默认浏览器。页面可以：

- 检查原版、已安装 Mod 或未知归档状态；
- 在安装前检查 Node.js、目录结构、受支持哈希、备份、游戏进程、权限和磁盘空间；
- 选择基础速度、行动 Zoom、永久金币倍率和 Turbo；
- 安装/重配并显示最新哈希状态；
- 从验证过的备份恢复原版；
- 下载脱敏诊断报告。

写操作要求用户先勾选“我已关闭游戏”；CLI 仍会独立检查 `SolCesto.exe`，因此 UI 确认不是唯一安全边界。

## 2. UI/API 安全模型

- 只监听 `127.0.0.1`，不绑定局域网地址；
- 精确验证 `Host` 和 `Origin`；
- 每次启动生成随机会话令牌，写请求必须通过自定义 Header 携带；
- 请求体限制为 32 KiB；
- 配置在服务端再次按枚举重建，不接受页面传入的额外字段；
- CLI 通过 `execFile` 参数数组调用，不拼接 shell 命令；
- 静态资源采用固定白名单并设置 CSP，不提供任意文件路径；
- UI 与 CLI 都限制单次操作，底层事务锁仍是最终并发保护。

## 3. 日志与诊断隐私

`operations.ndjson` 采用 512 KiB 自动轮换，只记录：

- 时间、命令、成功/失败、结果和耗时；
- 游戏版本与归档 SHA-256；
- 速度、Zoom、金币和 Turbo 枚举；
- 恢复结果及标准化错误类别。

它不记录错误消息或堆栈，因此不会把路径间接带入日志。诊断报告另使用独立字段白名单，并声明：不含个人路径、游戏文件、存档和 Epic 配置。

## 5. 候选发布包

构建：

```powershell
node tools\build-release.mjs
node tools\test-release-bundle.mjs
```

产物位于 `dist/fast-cesto-v0.1.0-alpha.1/` 及同名 ZIP。构建器只复制固定白名单，并审计：

- 禁止 `assets.dat`、游戏 EXE、DLL、`package.json`、安装状态、事务文件和操作日志；
- 禁止数据库、日志和超过 5 MiB 的意外文件；
- 禁止常见凭证模式、开发工作区绝对路径和用户目录；
- 为所有 payload 文件生成大小与 SHA-256 manifest。

当前候选包共 20 个文件，ZIP 大小 `42,517` 字节，SHA-256：

```text
FBDE8E1801B432829AD4DBF030F40B84081AAA7817FA208FCFF35B1F43EEB312
```

该哈希只对应当前本机构建候选；任何代码或发布文档变化后必须重新构建并更新。

## 6. 进入公开 Alpha 前后

候选包已经包含 `ALPHA-TESTING.md` 和 `FEEDBACK-TEMPLATE.md`，达到“可交给外部测试者”的技术形态。发布渠道确定为公开 GitHub Pre-release，反馈渠道为 Alpha 测试 Issue 表单；公开 Alpha 重点收集：

- 默认和自定义 Epic 安装路径；
- Windows 10/11、非 ASCII 路径、不同 DPI 和安全软件；
- 安装、重配、恢复及自然中断后的诊断报告；
- Turbo 暂停/切场景、金币其他分支和完整 Run；
- Node.js 前置条件是否构成明显使用障碍。
