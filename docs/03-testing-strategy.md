# 测试策略与职责划分

## 1. 核心结论

功能开发阶段的大部分测试可以由 Codex 在当前电脑上完成，但公开发布所需的兼容性和主观体验测试不能完全由一台机器覆盖。

预计职责分配：

| 负责人 | 比例 | 主要内容 |
|---|---:|---|
| Codex | 70%–80% | 自动化、补丁逻辑、本机集成、恢复与回归 |
| 用户 | 10%–15% | 主观节奏、镜头舒适度、真实游玩验收 |
| 外部测试者 | 10%–20% | 跨机器、安装路径、系统和安全软件兼容 |

因此，“功能能工作”可以主要由 Codex 验证；“可以放心公开发布”必须经过小规模外部 Beta。

截至 2026-08-11，Codex 已完成原版/原型启动、固定 1.5× 冒烟、行动 Zoom 相同输入 A/B、短程移动与结算、安装/恢复/再次安装。当前剩余重点已经从“能不能做”转为用户长 Run、主观体验、Epic 集成和跨机器兼容。详见 [08-prototype-validation-and-next-tests.md](08-prototype-validation-and-next-tests.md)。

同日已加入永久金币 2× 原型：20 个收入动作和 20 个等价副本通过自动验证，消费、读档、官方赠送和剧情奖励未被复制；游戏可正常启动。用户随后完成一次正常永久金币结算，确认实际余额增加 `2×`，基础加速仍生效且整体体验明显改善。其他金币收入分支仍按测试矩阵逐项覆盖。

Turbo Worker 预览也已完成第一轮动态测试：左 Shift `off → on → off`、按住后窗口失焦强制回到 `off`、右 Shift 不触发；原游戏事件中没有左 Shift 绑定。用户已确认真实玩法中 Turbo 有效，本机现安装 Turbo Preview；尚未完成暂停与场景切换回归，公开默认仍关闭。

补丁器安全测试已覆盖 8 种有日志的中断落点、活动/陈旧操作锁、孤立 stage 清理、无日志 swap 拒绝、游戏运行中拒绝、磁盘空间不足预检，以及完整 235 MB 归档的安装—恢复—再安装往返。真实断电不主动制造，恢复策略由日志与实际文件哈希共同决定。

## 2. 测试层次

### A. 静态与单元测试

由 Codex 完成：

- 原始文件指纹识别；
- 支持版本与未知版本判定；
- 补丁定位唯一性；
- 补丁前置条件和后置条件；
- 配置解析与非法配置处理；
- 备份命名、校验与恢复；
- 模拟写入失败、空间不足、文件被占用和权限不足；
- 重复安装、重复卸载和重复恢复的幂等性；
- Release ZIP 内容和哈希生成。

### B. 本机集成测试

由 Codex 在正版 Epic 安装上执行：

- 原版基线启动；
- 1× 与原版行为对比；
- 1.25× / 1.5× / 2× 分别运行；
- 开关 Zoom 前后对比；
- Turbo 按下、松开、切换场景和失去焦点；
- 菜单、商店、Boss、死亡、通关和返回主菜单；
- 新存档、已有存档、局外成长、奖励结算；
- 成就和 Epic Overlay 是否仍正常；
- 游戏更新、验证文件、恢复原版后的行为；
- 异常退出后是否留下半修改文件。

### C. 用户体验验收

需要用户亲自判断：

- 1.25×、1.5× 和 2× 哪些值得保留；
- 默认倍率应该是什么；
- Turbo 使用鼠标、键盘还是两者；
- 关闭 Zoom 后是否明显改善不适；
- 是否误伤 Boss、秘密房间或有观赏价值的镜头；
- 长时间游玩是否觉得动画反馈不足或节奏过快。

建议用户至少完成：

- 15–20 分钟快速体验；
- 一次包含商店、特殊房间和 Boss 的较完整 Run；
- 一次安装、卸载和重新安装体验。

### D. 外部兼容性测试

公开发布前至少覆盖：

- 3 台彼此独立的 Windows 电脑；
- Windows 10 与 Windows 11（如能招募到）；
- Epic 默认安装目录与自定义目录；
- 包含空格、非 ASCII 字符的路径；
- 100%、125%、150% 显示缩放；
- 不同分辨率或宽高比；
- Windows Defender，以及至少一种常见第三方安全软件环境；
- 有旧存档和全新存档的用户。

## 3. 核心功能测试用例

### 安装和恢复

1. 干净原版可以被正确识别；
2. 安装前自动生成备份；
3. 安装成功后目标文件符合预期哈希；
4. 重复安装不会叠加补丁或损坏文件；
5. 游戏运行中尝试安装时应安全拒绝；
6. 恢复后所有被修改文件与原始哈希一致；
7. 未知版本不得出现“强制继续”默认选项；
8. 写入中断后可以恢复到原版或完整 Mod 状态，不能停在中间状态。

### 速度功能

1. `1×` 与原版计时和表现一致；
2. 各倍率切换立即生效且不会累计；
3. Turbo 松开后可靠恢复此前倍率；
4. Alt+Tab、菜单暂停、场景切换后倍率正确；
5. 音频不发生不可接受的变调、重叠或丢失；
6. Tween、粒子、输入窗口和奖励结算不会跳过；
7. 同一初始条件下，概率与随机结果没有因帧率产生系统性改变。

### Zoom 功能

1. 只阻止目标行动 Zoom；
2. 菜单缩放、分辨率适配不受影响；
3. Boss、开场和秘密演出按产品决定保留；
4. 连续快速行动不会产生缩放漂移；
5. 开关设置持久化且恢复原版后不残留。

### 永久金币倍率

1. `1×` 与原版结算完全一致；
2. `2×/3×` 只放大永久金币收入，倍率不累计；
3. 正常过渡、死亡保留、特殊离场、存入金币和出售物品分别覆盖；
4. 购买扣款、退款、官方 Offer、剧情赠送和已有余额保持原版；
5. 当前余额与累计获得量保持一致；
6. 奖励文本或动画若仍显示原始值，必须明确修复或记录；
7. 从 `2×` 切回 `1×` 不回滚已获得金币，也不再次处理已有余额；
8. 每次测试前记录 `or` 值，只读核对结算前后差额。

## 4. 存档与游戏状态安全

金币倍率不直接重写既有存档，但会有意改变后续收入，仍需要防止间接损害：

- 第一次测试前复制存档并记录哈希；
- 测试过程中比较存档目录新增、修改和删除情况；
- 验证局外金币、解锁、牙齿、角色和设置仍正常；
- 当前用户环境没有可用的云存档恢复，因此本地备份更加重要；
- 对损坏或不同步风险使用专门测试存档，不拿唯一主存档冒险。

## 5. 发布门槛

### Alpha 门槛

- 本机原版、安装、运行、恢复全链路通过；
- 10 次安装—恢复循环无文件差异；
- 至少一次较完整 Run；
- 没有 P0/P1 问题。
- 金币 2× 的正常结算已通过；死亡或特殊结算至少一种仍需通过；

### Beta 门槛

- 至少 3 台外部电脑成功；
- 默认与自定义路径均通过；
- 合计至少 5 次较完整 Run；
- 零游戏文件或存档损坏；
- 未知版本安全拒绝率 100%；
- 所有已知问题已记录并给出规避方式。

### Stable 门槛

- 公开 Beta 至少运行 7 天；
- 没有未解决 P0/P1；
- 安装、恢复说明由未参与开发的测试者成功照做；
- Release 文件哈希、来源证明和文档完整；
- 开发者/发行方公开发布态度已经确认或风险已作明确决定。

严重级别：

- **P0**：损坏正版安装、存档丢失、安全问题；
- **P1**：无法启动、无法恢复、广泛崩溃、游戏结果被错误改变；
- **P2**：单个场景失效、UI 问题、可规避兼容问题；
- **P3**：文字、排版和轻微体验问题。

## 6. Auto Clear 的额外门槛

Auto Clear 不与首版共用同一发布门槛。它需要：

- 建立游戏状态模型；
- 列举所有可能改变选择价值的道具、牙齿、诅咒和秘密条件；
- 对自动执行与手工执行进行结果对照；
- 验证随机数调用次序、奖励、成就和隐藏解锁；
- 默认关闭并标为 Experimental；
- 另行进行社区 Beta。

在这些条件满足前，只允许做“加速剩余动画”，不允许自动替玩家选择。

## 7. 外部 Bug 报告所需信息

Issue 模板至少收集：

- Mod 版本；
- 游戏商店版本（Epic/Steam）；
- 游戏 EXE/资源哈希，由工具自动生成匿名诊断文本；
- Windows 版本；
- 安装路径类型（默认/自定义，不要求公开用户名部分）；
- 启用的功能与倍率；
- 重现步骤、期望结果、实际结果；
- 本地日志；
- 是否可以通过 Restore 恢复。

诊断信息不得包含 Epic 账号、用户真实姓名、存档内容或其他无关个人数据。
