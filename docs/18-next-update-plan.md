# Fast Cesto 下一阶段更新计划

> 制定日期：2026-08-21
> 当前公开版本：`v0.2.0-alpha.1`
> 下一候选版本：待外部反馈后决定
> 本计划依据：[Bilibili 专栏及评论](https://www.bilibili.com/read/cv52257808/)、GitHub Release 状态和当前代码/测试覆盖。

## 1. 新证据与结论

截至 2026-08-21，公开反馈中出现了第一位明确确认实际使用成功的外部用户：

- “感谢制作 太好用了”；
- 随后提出：“是否考虑做个减速按钮？第四关的炸弹怪和手陷阱能用到。”

这两句话分别提供了不同层级的证据：

1. 当前 Epic Windows `1.01.3` 公开包至少在另一名真实用户的环境中完成了安装与实际使用；
2. 第四区域存在需要更多反应时间的具体场景；
3. 用户想要的是临时、可控的减速，而不是把整局基础速度永久调慢。

GitHub `v0.1.0-alpha.2` ZIP 当前有 8 次下载。下载次数只能视为传播信号，不能等同于 8 名成功用户。当前可确认的外部成功样本仍为 1 名，因此暂不升为 Beta。

### 1.1 Epic `1.01.4b` 更新复核

2026-08-21 Epic 客户端更新后，玩家可见版本为 `1.01.4b`，归档内部项目版本为 `1.01.4`。新版原版 `assets.dat` SHA-256 为 `3265599AE2CF79F650C22C33E56CE4DA83BF0655B24E67447208D3C7FAEEFC69`；旧工具按设计将其识别为未知构建，没有修改文件。

新旧归档比较显示：Construct 运行时哈希未变，但 `data.json`、对象引用表、数据表和大量图像资源已更新。完成以下兼容复核后，下一候选版的支持目标迁移到 `1.01.4b`，旧 `1.01.3` 由历史 Release 保留且不会被新工具接受：

- 16 种基础速度/Turbo/Focus 组合均唯一命中运行时锚点；
- 6 种 Zoom/金币组合均命中原有 20 个金币动作和唯一 Zoom 动作；
- 第四区域炸弹 Timer 与手墙陷阱 Tween/致死链自动审计通过；
- 新版实机启动到 Construct 页面，Ctrl Focus、Shift Turbo、两键重叠和失焦复位均通过 WebView 输入验证；
- 使用独立 `backups/epic-1.01.4b` 完成安装、逐字节恢复新版原版和再次安装，旧版备份未被覆盖。

## 2. 下一版产品决定

下一版主功能定为：**按住减速（Focus / Slow）**。

它与现有 Turbo 形成一套完整的临时节奏控制：

- 平时使用选定的基础速度；
- 清场或重复操作时按住 Turbo 加速；
- 炸弹怪、手陷阱等需要反应时按住 Focus 减速；
- 松键后立即回到此前状态。

该功能先作为可选 Alpha 功能发布，默认关闭。验证通过后再决定是否在推荐配置中默认开启；基础速度、金币倍率和 Zoom 现有默认值不变。

下一版采用 `v0.2.0-alpha.1`，因为这是新增用户可见功能，而非单纯修补 `v0.1.0-alpha.2`。

## 3. 功能定义

### 3.1 用户界面

中英文界面新增一个与 Turbo 并列的区域：

- 中文：`按住减速`，说明文字中可使用“专注模式”；
- 英文：`Hold for Focus`，辅助说明为临时 slow motion；
- 开关：默认关闭；
- 按键：先提供左/右 `Ctrl`，其中左 `Ctrl` 为预览默认值；
- 目标速度：`0.5× / 0.75× / 1×`，预览默认 `0.5×`。

静态扫描未发现游戏事件表使用左/右 `Ctrl`；实现前仍需在真实玩法、菜单和输入框中做一次冲突确认。

### 3.2 速度语义

Focus 使用“相对原版的目标速度”，不使用“在当前基础速度上再乘一个倍率”。例如：

| 当前状态 | 实际速度 |
|---|---:|
| 基础速度 | 用户选定的 `1× / 1.25× / 1.5× / 2×` |
| Turbo | 基础速度 × Turbo 倍率 |
| Focus | 用户选定的绝对目标 `0.5× / 0.75× / 1×` |

这样无论基础速度是 `1×` 还是 `2×`，`0.5×` Focus 都提供一致、易理解的双倍反应时间目标。

游戏自身设置的暂停、冻结和特殊 time scale 必须继续生效。Focus 不能把游戏自己的 `0` 倍暂停强行改成非零。

### 3.3 状态优先级

同时按住 Focus 与 Turbo 时：**Focus 优先**。

推荐状态机：

1. 两者都未按：基础速度；
2. 只按 Turbo：Turbo 速度；
3. 只按 Focus：Focus 目标速度；
4. 两者都按：Focus 目标速度；
5. 松开 Focus 而 Turbo 仍按住：恢复 Turbo；
6. 窗口失焦、键盘失焦、挂起或读档：清除两个临时状态，恢复基础速度。

该规则优先保证反应时间，并避免按键重叠后卡在错误倍率。

## 4. 实施阶段

### M6a：配置与运行时

- 配置升级到 schema v3，新增独立 `focus` 对象；
- 旧 schema v2 配置应自动迁移为“Focus 关闭”，不能让现有用户升级后配置失效；
- 将现有 Turbo 单状态逻辑重构为基础速度、Turbo、Focus 三态计算；
- 处理按下、松开、重复 keydown、两键重叠、窗口失焦、挂起和读档；
- 保留 Construct 3 原有暂停/冻结语义；
- 增加中英文状态提示、诊断字段和安装状态摘要；
- 新增 `focus-preview` 配置，但公开默认配置仍关闭 Focus。

### M6b：自动化与静态验证

由 Codex 完成：

- schema v2 → v3 迁移、v3 严格校验及非法配置拒绝；
- 运行时补丁的唯一命中、标记和恢复验证；
- Focus 按下/松开、按键重复和左右键选择；
- Focus 与 Turbo 的所有重叠顺序；
- blur、keyboard-blur、suspend、load 后不残留临时倍率；
- 游戏内部 time scale 为 `0` 或其他值时的组合计算；
- UI 中英文完整性、摘要联动和窄屏布局；
- 安装、跨配置重建、恢复、诊断脱敏和 Release ZIP 冒烟；
- Release 白名单审计，继续确保不分发游戏文件、存档或本机路径。

### M6c：第四区域判定自动审计与可选实机确认

无需为测试反复打到第四区域或故意等待角色死亡。精确 Epic `1.01.4b` 构建的自动审计已经闭环验证：

1. 炸弹怪的危险窗口来自 `TempsExplosion = 20` 的 Timer；Timer 每帧累加实例的缩放 `dt`；
2. 玩家所称的手陷阱在事件表中是 `pieges - murs`，关闭窗口来自 `tempsDispo = 4.5` 的 Tween；
3. Tween 完成后调用 `murKill`，将英雄生命直接设为 `0`；该 Tween 使用系统 time scale，组内 Wait 也全部使用游戏时间；
4. Focus `0.5×` 因而把炸弹窗口从原版约 20 秒扩展为约 40 秒，把手墙陷阱窗口从约 4.5 秒扩展为约 9 秒；相对当前基础 `1.5×`，两者的现实反应时间均扩大为 3 倍；
5. 自动测试固定检查原版归档哈希、事件/动作 SID、运行时时钟实现和 Focus 补丁标记，游戏更新或链路变化会使测试失败。

自动审计解决的是“判定是否真的随画面减速”这一客观发布风险。普通房间的按键手感、Ctrl 冲突、暂停/切房/Alt+Tab 复位和音频体验仍适合短程实机测试；若正常游玩时自然遇到第四区域危险，可顺手确认一次主观体验，但这不再是发布前置条件。完整依据与复现命令见 [`20-hazard-timing-automation.md`](20-hazard-timing-automation.md)。

### M6d：外部验证与发布

先生成仅供本机和定向用户测试的候选包，再发布 `v0.2.0-alpha.1`：

- Codex 完成危险判定自动审计、常规自动化、安装恢复、包内容和文档验证；
- 你只需完成方便抵达的普通玩法、按键重叠、暂停/场景/Alt+Tab 和主观音频测试；
- 发布后邀请提出需求的用户复测，但不要求其承担完整 QA；
- 重点询问：Focus 是否好用、是否有卡慢速、按键是否冲突；第四区域反馈仅在自然遇到时收集；
- 收到至少一份外部 Focus 有效反馈后，再决定是否把 Focus 从“预览”改为普通选项；
- 继续收集 Windows 路径、DPI和安全软件差异，不因单个成功样本进入 Beta。

## 5. 发布门槛

`v0.2.0-alpha.1` 必须同时满足：

- 自动化测试全部通过；
- 原版恢复哈希验证通过；
- schema v2 用户可以无损升级；
- Focus、Turbo 单独及重叠均不残留错误倍率；
- `node tools/test-hazard-timing.mjs` 在精确原版备份上通过，确认减慢的是有效反应窗口而不只是视觉动画；
- 中英文 UI、README、测试指南、反馈模板和已知问题同步；
- Release 包不含游戏资源、存档、凭证、日志或绝对开发路径；
- Steam 版仍明确标为未支持、未验证。

## 6. 本轮不纳入

- **Steam 版兼容**：继续寻找正版持有者或接力开发者，独立取得文件哈希并验证；不能用 Epic 版本相似来宣称支持。
- **Auto Clear**：需要判定“无决策残局”，错误风险远高于临时变速，暂不与本次小版本捆绑。
- **直接修改存档或一次性大量金币**：当前金币倍率已覆盖主要重开档需求。
- **Beta/Stable 宣传扩张**：先把当前真实用户转化为高质量反馈闭环，再扩大渠道。
- **捆绑 Node.js 或单文件程序**：仍是降低安装门槛的候选工作，但现有公开包已有外部成功案例，本轮优先解决已验证的玩法需求。

## 7. 后续优先级

Focus 发布并观察后，按以下顺序重新评估：

1. 补齐 Turbo/Focus 长局、Boss、死亡和特殊金币结算覆盖；
2. 降低 Node.js 安装门槛；
3. 获取 Steam 正版环境并做只读兼容性研究；
4. 根据真实反馈决定 Auto Clear 是否值得进入原型；
5. 达到 3–5 台独立环境、恢复可靠且无高优先级问题后，再讨论公开 Beta。

## 8. 下一步

计划确认后，从 M6a 开始实现。第一份可试玩产物应是本机 `focus-preview`，不是直接发布 GitHub；危险判定自动审计和普通房间短程体验通过后再决定是否发布公开候选包。
